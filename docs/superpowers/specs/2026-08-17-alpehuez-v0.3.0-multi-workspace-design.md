# AlpeHuez v0.3.0 地基：多工作台架构（车队模式）设计

日期：2026-08-17
状态：已批准（用户确认）

## 背景与目标

AlpeHuez v0.2.0 是单工作台桌面导航面板。v0.3.0 引入"车队模式"多工作台架构：一个用户拥有多个个人工作台（车手），在同一个 App 内用顶部标签页切换，每个工作台代表一个车手，拥有独立的链接集、配置与（后续的）待办/专注/成就数据。

本 spec 覆盖 **P0 地基**：多工作台数据层、切换 UI、每工作台独立链接集、工作台管理、深色模式修复、浅色模式调色板、Settings 文案精简、内部网页加载蒙层、数据库版本控制。另含 **P1 HF 备份**（用户数据备份到 Hugging Face 私有仓库）。其余子项目（About 车手档案、环法荣誉衫、专注热力图、悬浮球、会议提醒、笔记集成、Git 时间线）在后续 spec 中单独设计。

## 已确认的决策

1. **主将统揽全局**：每工作台数据独立存储，但主将工作台拥有聚合看板视角（聚合逻辑在后续子项目实现，地基阶段只建数据模型）。
2. **每工作台独立链接集**：主将工作台 → 全局 `links.json`（部署站点继续可用）；副将工作台 → SQLite 独立链接集（仅 App 内）。
3. **初始 5 个工作台**：主将 + 平路副将 + 山地副将 + 古典赛副将 + 带冲手。
4. **车手指标先手动后自动**：About 的 specialties（GC/Climber/Sprint/TT）v0.3.0 手动设置，专注追踪完成后切换为自动计算。
5. **外部服务约束**：地基 100% 本地实现，不依赖任何外部服务。后续子项目如需外部服务（如天气），仅用免费档（Open-Meteo 等），且先与用户确认。
6. **单 WebView + 状态快照**：工作台切换不创建独立 WebView。主窗口保持一个 index.html WebView，切换时重新渲染链接数据 + JS 快照/恢复该工作台 UI 状态。外部网页（监控看板等）已是独立 child WebView，切换工作台时保持存活，会话不丢。
7. **数据库版本控制**：SQLite `PRAGMA user_version` 记录 schema 版本（当前 1），未来迁移用版本号驱动。
8. **HF 备份（P1）**：所有用户数据备份到用户 HF 私有 Dataset 仓库（免费档），详见"HF 备份"章节。

## 架构

### 数据层：SQLite（rusqlite）

新增 `rusqlite` 依赖（bundled 特性，避免系统 SQLite 依赖）。数据库文件位于 `app_data_dir/alpehuez.db`。

地基阶段 3 张表：

**`workspaces`**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自增 |
| name | TEXT | 工作台显示名（如"主将"） |
| role | TEXT | `leader` 或 `domestique` |
| rider_type | TEXT | Rider Type（GC Contender / Rouleur / Climber / Puncheur / Lead-out Man） |
| rider_name | TEXT | 车手名 |
| rider_number | INTEGER | 车手号 |
| specialties | TEXT | JSON：`{"gc":0,"climber":0,"sprint":0,"tt":0}`（0-100，手动值） |
| sort_order | INTEGER | 标签栏排序 |
| created_at | TEXT | ISO 时间 |

**`workspace_links`**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| workspace_id | INTEGER PK | 关联 workspaces.id |
| links_json | TEXT | 该工作台的独立链接集（与 links.json 同构） |

**`app_config`**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| key | TEXT PK | 配置键 |
| value | TEXT | JSON 值 |

`app_config` 逐步替代 `config.json`（密码、背景、浏览器配置等暂不迁移，保持向后兼容）。

**版本控制**：初始化时 `PRAGMA user_version = 1`。未来 schema 变更时，按版本号顺序执行迁移脚本，避免用户数据丢失。

### 种子数据

首次启动（数据库不存在时）自动创建 5 个工作台：

| name | role | rider_type | 职责 |
| --- | --- | --- | --- |
| 主将 | leader | GC Contender | 核心工作台，继承全局 links.json |
| 平路副将 | domestique | Rouleur | 日常琐事 / 邮件 / 会议 |
| 山地副将 | domestique | Climber | 深度阅读 / 文献管理 |
| 古典赛副将 | domestique | Puncheur | 短陡坡攻坚 / 突发任务 |
| 带冲手 | domestique | Lead-out Man | 冲刺 / 高频快速任务 |

主将工作台不写入 `workspace_links`（读全局 links.json）；副将工作台写入空链接集（`{"icons":[]}`），由用户在面板中填充。

### 工作台切换 UI：顶部标签栏

- 主窗口顶部新增水平标签栏（浏览器风格），位于 Activity Bar 之上。
- 每个标签：车手名 + 类型徽章（主将带皇冠图标）。
- 标签栏右侧 "+" 按钮：新建工作台弹窗（名称、角色、Rider Type、车手名、车手号）。
- 标签右键菜单：重命名 / 删除 / 设为角色。
- 当前工作台 id 持久化到 `app_config`（key: `active_workspace`）。
- 切换动画：150ms 交叉淡入淡出 + `translateY(4px)` 位移（换挡感）。
- 状态快照：切换前保存当前工作台的 UI 状态（当前 context、侧栏开合、滚动位置、搜索词），切换后恢复。
- 删除工作台时若为当前工作台，自动切换到第一个剩余工作台；主将工作台不可删除。

### 前端改造（index.html）

- 新增顶部标签栏组件（HTML + CSS + JS）。
- 页面加载时通过 IPC 获取工作台列表 + 当前工作台，渲染标签栏。
- 切换工作台：IPC 拉取该工作台链接集 + 配置 → 重新渲染 Portal 视图。
- 主将工作台读全局 links.json；副将读 SQLite `workspace_links`。
- 非 Tauri 环境（浏览器直接打开 index.html）时标签栏隐藏，保持部署站点行为不变。
- 浅色模式调色板：`html[data-theme="light"]` 定义冰雪蓝 `#B1E3FF` 底层环境光 + 暖麦色 `#FFE0AE` 点缀 + 白色玻璃拟态卡片（`rgba(255,255,255,0.6)` + `backdrop-filter: blur`）。
- Settings 文案精简：`Interface Settings` → `Settings`，`Support the author` → `Support`（i18n 字典 + HTML 两处）。
- 内部网页加载蒙层：WebView 容器上方覆盖 Loading 蒙层，中央为品牌蓝 `#0087EB` 的旋转自行车牙盘 SVG 动画；监听页面加载完成事件后渐隐移除，消除黑屏。

### Rust 命令（新增）

| 命令 | 说明 |
| --- | --- |
| `list_workspaces` | 返回全部工作台（含 specialties） |
| `get_active_workspace` | 返回当前工作台 id |
| `set_active_workspace(id)` | 设置当前工作台并持久化 |
| `create_workspace(name, role, rider_type, rider_name, rider_number)` | 新建工作台 |
| `update_workspace(id, ...)` | 更新工作台字段 |
| `delete_workspace(id)` | 删除工作台（主将不可删） |
| `get_workspace_links(id)` | 返回工作台链接集（主将返回全局 links.json） |
| `save_workspace_links(id, data)` | 保存副将链接集 |
| `get_app_config(key)` | 读配置 |
| `set_app_config(key, value)` | 写配置 |

所有命令在 `src-tauri/build.rs` 的 `AppManifest::commands([...])` 中声明，并在 `capabilities/nav-site.json` 中授权（nav:// 页面需要）。

### 面板改造（panel/）

- 新增"工作台管理"界面：增删改工作台、设置角色/Rider Type/specialties。
- 链接编辑按当前工作台切换目标（主将 → links.json，副将 → SQLite）。

### 深色模式修复

- 最外层强制暗色统治：`html[data-theme="space"], html[data-theme="space"] body { background-color: #0B1120 !important; color: #E2E8F0; }`。
- 所有卡片/面板容器转深色玻璃态：`rgba(30, 41, 59, 0.7)` + `backdrop-filter: blur(12px)`。
- 排查 `html[data-theme="space"]` 下漏出白底的组件（背景图、卡片、面板、弹窗等），消除内部组件多余边距导致的漏白。

## 错误处理

- SQLite 打开/迁移失败：返回错误字符串，前端提示。
- 删除主将工作台：拒绝并返回错误。
- 非 Tauri 环境调用 IPC：前端检测 `isDesktop`，标签栏隐藏，不调用 IPC。

## 测试

- Rust 单元测试：workspaces CRUD、种子数据创建、主将链接回退逻辑。
- 手动验证：启动 App → 5 个标签 → 切换工作台 → 链接集切换 → 面板编辑副将链接 → 深色模式无漏白。

## HF 备份（P1，地基完成后实现）

**目标**：AlpeHuez 所有用户数据（SQLite DB、config.json、副将链接集）备份到用户 HF 私有 Dataset 仓库，保证数据不丢失。

**免费档**：HF Datasets 私有仓库免费，存储额度足够个人备份。

**参考现有模式**（`D:\YL2026\appflowy-backup`，只读参考，不修改）：
- HF 私有 Dataset 仓库当 git remote：`https://huggingface.co/datasets/Helloxiaolaodi/<repo>.git`
- token 从 `C:\Users\Lenovo\.cache\huggingface\token` 读取，内联 Basic Auth
- 二进制文件走 Git LFS + Xet（HF 要求），`.gitattributes` 声明 `*.db filter=lfs`
- 走代理 `http://127.0.0.1:7897`（中国大陆访问 HF 需要 VPN）
- 快照 → git add/commit/push，Windows Task Scheduler 定时触发

**AlpeHuez 落地**：
- 备份目标：HF 私有 Dataset 仓库 `Helloxiaolaodi/alpehuez-backup`（新建，用户可改）。
- 本地备份目录：`D:\YL2026\alpehuez-backup`（独立于 my-nav 仓库，避免污染 GitHub 推送）。
- 备份内容：`alpehuez.db`（SQLite）+ `config.json` + 副将链接集导出。
- 新增 Rust 命令：`hf_backup`（快照+commit+push）、`hf_restore`（pull+恢复）、`hf_test_connection`。
- 触发：面板手动备份按钮 + App 退出时自动备份。
- 需要用户提供：HF token（或确认 `~/.cache/huggingface/token` 已存在）、确认新建 `alpehuez-backup` 私有仓库。

**安全**：token 仅从本地 `~/.cache/huggingface/token` 读取，不写入仓库；备份文件含敏感数据，仓库必须为私有。
